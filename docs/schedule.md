# 정기 실행 안전장치

GitHub 의 정기 실행(schedule, cron)은 약속된 시각에 꼭 돌지 않는다. 바쁠 때는 몇 시간씩 늦거나 아예 빠진다.

## 실제로 있었던 일 (2026-11-22 밤 ~ 11-23 새벽, UTC 기준)

- 15:15 UTC 뒤로 약 5시간 동안 정기 실행이 하나도 들어오지 않았다.
- 늦게라도 돈 것: 유튜브 키트(13:07 예정 → 20:15), 정비사업·살아보니 거르기(17:37·17:41 예정 → 22:45), 단지 시설(17:37·17:57 예정 → 22:42·23:15). 모두 5~7시간 늦었다.
- 18:00 UTC 이후로 잡힌 것은 08:25 KST 까지 하나도 오지 않았다: update(18:21), 주간 계산(18:43~20:13), 모닝 브리핑(20:07~21:37), 감시(20:13~), 주간 발표(22:00~), 내 집 성적표(22:52), 검색용 페이지(22:37).
- 원인은 워크플로 파일이 아니다. 전날 저장소 기록을 다시 쓴 일(force-push)과도 관계없다:
  - 워크플로 번호(id)·파일 경로는 그대로였고, 같은 이름의 꺼진 중복도 없었다(모두 active).
  - force-push 뒤에 한 번도 고치지 않은 파일(유튜브 키트·정비사업·단지 시설)도 늦게나마 돌았고, force-push 뒤에 고친 update.yml 도 14:40 UTC 에 돌았다.
  - 빠진 것과 돈 것을 가르는 것은 '예정 시각'뿐이었다(18:00 UTC 전 = 늦게 돎, 뒤 = 안 옴). 즉 GitHub 쪽 정기 실행 대기열이 밀린 것이다.
- 11-22 아침에도 모닝 브리핑 정기 실행이 4시간 늦게(09:17 KST) 들어온 적이 있다.

## 지금 있는 장치 (3겹)

1. **예비 정기 시각 + 확인 단계** — brief·weekly·weekly_release·seo·report 는 정기 시각을 4개씩 두고, 맨 앞 '확인'(`.github/scripts/sched.py guard`)이 오늘 이미 성공했으면 본 작업을 건너뛴다. 늦게 도착한 정기 실행도 여기서 걸러져 두 번 만들지 않는다.
2. **감시(watchdog.yml) 정기 실행** — 05:13~08:43 KST 30분마다 + 3시간마다. 해야 할 시각이 지났는데 성공도, 도는 중인 실행도 없으면 GITHUB_TOKEN(actions: write)으로 다시 실행(workflow_dispatch)한다. 워크플로마다 하루 최대 2번.
3. **감시의 두 번째 깨우개: 다른 워크플로가 끝날 때(workflow_run)** — GitHub cron 이 아니라 '어떤 워크플로든 끝났다'는 일로 깨어난다. 단지 시설(하루 8번)·update·건물 위치·정책 수집·살아보니 거르기·정비사업·유튜브 키트·모닝 브리핑·주간 계산·주간 발표·검색용 페이지·주간 현장 보고서 중 하나라도 끝나면(늦게라도) 감시가 같은 확인을 하고 빠진 것을 다시 실행한다. 다시 실행된 브리핑·주간 계산이 끝나면 그것이 또 감시를 깨워 다음 순서(주간 발표 등)를 챙긴다.
   - update.yml(6시간마다)은 '최근 9시간 동안 시작된 실행이 하나도 없으면' 다시 실행한다.
   - 이렇게 깨어난 감시는 다시 실행을 요청했을 때만 data/schedule_health.json 에 기록한다(쓸데없는 커밋 방지).
   - 새 비밀값(secret)은 필요 없다. GitHub 은 GITHUB_TOKEN 으로 만든 push 로는 다른 워크플로를 깨우지 않지만, workflow_dispatch 요청과 workflow_run 은 예외라 이 방식이 된다.

## 주의

- 위 워크플로의 `name:` 을 바꾸면 watchdog.yml 의 `workflow_run.workflows` 목록도 같이 바꿔야 한다(이름으로 연결됨).
- 감시가 확인하는 목록과 시각은 `.github/scripts/sched.py` 의 `WF`(하루 한 번 할 일)·`INTERVAL`(몇 시간마다 할 일)에 있다. 워크플로 cron 을 바꾸면 여기도 같이 바꾼다.
- 모든 정기 실행이 한꺼번에 밀리면 3번 장치도 깨어날 계기가 줄어든다. 더 단단하게 하려면 GitHub 밖(예: Apps Script 시간 트리거)에서 workflow_dispatch 를 부르는 방법이 있지만, 그때는 actions 쓰기 권한이 있는 토큰을 새로 넣어야 한다.
- 모닝 브리핑을 같은 날 두 번 돌리면 두 번째는 '새로 올라온 거래'가 거의 0건이 된다(첫 실행이 이미 본 거래로 기록). 수동으로 다시 돌리기 전에 오늘 성공한 실행이 있는지 먼저 본다.
